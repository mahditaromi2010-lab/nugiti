# Nogiti Platform — بازسازی و یکپارچه‌سازی سایت

این بسته یک پایهٔ اجرایی Node.js برای بازسازی Nogiti است: صفحهٔ عمومی، ابزارهای محاسبات تأسیسات، فروشگاه دوره/افزونه، مقاله‌ها، حساب کاربری، کنترل محتوای مدیر، سفارش‌ها و اتصال قابل پیکربندی به Kavenegar و ZarinPal.

> وضعیت این بسته: نسخهٔ اولیهٔ یکپارچه (MVP) برای بررسی و ادامهٔ توسعه است؛ به معنای تأیید نهایی فنی مقررات تأسیسات یا آماده‌بودن برای دریافت پول در محیط واقعی نیست. درگاه و پیامک تا زمان ورود کلیدهای معتبر و آزمایش انتهابه‌انتها فعال نیستند.

## فناوری و ساختار

- Node.js 20+ / Express و EJS برای یک برنامهٔ واحد و قابل استقرار.
- PostgreSQL برای کاربران، کدهای ورود، محصولات، محتوا، مقالات، سفارش‌ها و تنظیمات.
- Session سمت سرور و cookie امن؛ کنترل نقش مدیر در سرور.
- بارگذاری تصویر شاخص، فایل خصوصی محصولات و ارائهٔ فایل‌ها از مسیر کنترل‌شده.
- درگاه پرداخت ZarinPal با درخواست و تأیید سمت سرور؛ قیمت در پنل به تومان است و مبلغ درگاه به ریال ارسال می‌شود.
- SMS از طریق Kavenegar در صورت تنظیم کلید API.
- هیچ Redis یا صف پس‌زمینه‌ای لازم نیست.

## راه‌اندازی محلی با Docker

1. فایل `.env.example` را به `.env` کپی کنید.
2. مقدار `POSTGRES_PASSWORD` را به یک گذرواژهٔ قویِ URL-safe (مثلاً خروجی `openssl rand -hex 24`) تغییر دهید و همان را در بخش گذرواژهٔ `DATABASE_URL` نیز قرار دهید. `APP_SECRET` باید حداقل ۳۲ نویسه تصادفی داشته باشد؛ برای نمونه از `openssl rand -hex 32` استفاده کنید.
3. اجرا کنید:

   ```bash
   docker compose up --build -d
   ```

4. ساخت حساب مدیر از داخل کانتینر برنامه:

   ```bash
   docker compose exec -e ADMIN_PHONE=09123456789 -e ADMIN_PASSWORD='A-long-unique-password' -e ADMIN_NAME='مدیر Nogiti' web npm run admin:create
   ```

5. سایت در `http://localhost:3000` و صفحه ورود مدیر در `/admin/login` در دسترس خواهد بود.

اگر محیط اجرا `docker compose` ندارد، Node.js و PostgreSQL سازگار نصب کنید؛ سپس:

```bash
cp .env.example .env
npm install
npm run db:migrate
npm start
```

حساب مدیر را با متغیرهای `ADMIN_PHONE`، `ADMIN_PASSWORD` و `ADMIN_NAME` هنگام اجرای `npm run admin:create` بسازید. دستور ساخت مدیر نباید در مسیر عمومی سایت در دسترس باشد.

## تنظیم پیامک Kavenegar

- `KAVENEGAR_API_KEY`: کلید API حساب Kavenegar.
- `KAVENEGAR_SENDER`: شمارهٔ فرستنده، در صورت نیاز حساب.
- در محیط production اگر کلید تنظیم نشده باشد، ورود با OTP شکست می‌خورد و کد نمایشی تولید نمی‌شود.
- در توسعه می‌توان `SHOW_DEV_OTP=true` قرار داد تا کد آزمایشی در خروجی سرور ثبت و در صفحه ورود نمایش داده شود. این گزینه نباید در production فعال باشد.

## تنظیم ZarinPal

- `ZARINPAL_MERCHANT_ID`: شناسهٔ پذیرندهٔ معتبر.
- `ZARINPAL_SANDBOX=true` برای آزمون در sandbox؛ برای محیط واقعی پس از آزمایش با مقدار `false` تنظیم شود.
- `APP_URL` باید نشانی عمومی HTTPS برنامه در محیط واقعی باشد تا callback پرداخت به مسیر `/payments/zarinpal/callback` برگردد. اگر TLS در reverse proxy یا لایهٔ PaaS خاتمه می‌یابد، `TRUST_PROXY=true` را تنظیم کنید تا کوکی امن به‌درستی عمل کند.
- مبلغ محصول در پنل به تومان ثبت می‌شود و سرویس مقدار متناظر ریالی را برای درگاه ارسال می‌کند. مبلغ، authority و پاسخ verify در سمت سرور بررسی می‌شوند. به query پارامتر بازگشت به‌تنهایی اعتماد نمی‌شود.

## مدیریت محتوا

### محصول، دوره یا افزونه

از پنل `/admin/products` محصول جدید بسازید، نوع دوره یا پلاگین، قیمت، توضیحات، تصویر شاخص و وضعیت انتشار را تعیین کنید. سپس از فرم ویرایش، فایل ویدئو (`.mp4`/`.webm`)، PDF، ZIP یا پیوند HTTPS خصوصی اضافه کنید. برای دوره می‌توان عنوان هر درس/منبع و ترتیب نمایش را ثبت کرد. برای فایل رایگان، گزینهٔ «پیش‌نمایش» را فقط در صورت نیاز روشن کنید.

**مهم:** برای فایل‌های ویدئویی حجیم یا سامانهٔ پرکاربر، ذخیره‌سازی پایدار یا object storage خصوصی با URL امضاشده، streaming/range، اسکن فایل و سیاست پشتیبان‌گیری لازم است. این نسخه فایل‌ها را در volume خصوصی برنامه نگه می‌دارد و مسیر فایل خصوصی از static server عمومی ارائه نمی‌شود. اگر PaaS فضای فایل پایدار ندارد، پیش از استقرار باید adapter ذخیره‌سازی به سرویس object storage متصل شود.

### مقالات

از `/admin/articles` عنوان، slug، دسته، خلاصه، متن، تصویر شاخص و وضعیت انتشار را ثبت کنید. تصویر شاخص از فایل یا نشانی HTTPS قابل تنظیم است. همچنین می‌توان حداکثر ۱۰ تصویر داخل مقاله بارگذاری کرد؛ بعد از ذخیره، برای هر تصویر یک کد مانند `[[image:12]]` نمایش داده می‌شود. قرار دادن کد در یک خط جداگانه از متن، تصویر را در همان محل مقاله نمایش می‌دهد. متن و کپشن‌ها به‌صورت امن escape می‌شوند و HTML خام در بدنه اجرا نمی‌شود.

### دسترسی مدیر

مدیر با شماره و گذرواژهٔ ساخته‌شده از فرمان `admin:create` وارد می‌شود. **ثبت‌نام عمومی، نقش مدیر ایجاد نمی‌کند**؛ مسیرهای `/admin/*` با نقش ذخیره‌شده در دیتابیس محافظت می‌شوند.

## محاسبات تأسیسات: محدودیت مهم

کد و داده‌های محاسباتی از فایل HTML ارسالی منتقل شده‌اند تا ویژگی فعلی از بین نرود؛ این انتقال به معنی اعتبارسنجی مقرراتی نیست. مقادیر و جدول‌های قطر لوله، دودکش، کنتور، هوای احتراق و ضرایب تبدیل باید پیش از ارائه به کاربر یا استفادهٔ اجرایی، با متن رسمی و ویرایش جاری مبحث ۱۷، واحدها و قواعد گردکردن کنترل شوند. ابزار به‌صورت واضح هشدار می‌دهد که نتیجه صرفاً برآورد اولیه است.

## چک‌لیست پیش از انتشار واقعی

- تنظیم دامنهٔ HTTPS، APP_URL، APP_SECRET و پیکربندی PostgreSQL production.
- آزمایش پیامک/OTP، محدودیت تعداد درخواست، انقضای کد و ورود مدیر.
- آزمایش سناریوهای پرداخت موفق، لغوشده، callback جعلی، callback تکراری و تأیید ناموفق درگاه.
- نهایی‌کردن سیاست قیمت، بازپرداخت، فاکتور و متن حقوقی خرید.
- اتصال فضای ذخیره‌سازی پایدار خصوصی برای فایل‌های بزرگ و تهیهٔ backup.
- بازبینی جدول‌ها و فرمول‌های تأسیسات توسط فرد متخصص و مقایسه با منبع رسمی جاری.
- اجرای audit امنیتی، تست مسیرهای مختلف موبایل و تست بارگذاری تصویر/ویدئو.

## مسیرهای اصلی

- `/` صفحه اصلی
- `/tools` ماشین‌حساب‌های تأسیسات
- `/shop` فروشگاه و `/shop/:slug` جزئیات محصول
- `/articles` مجله و `/articles/:slug` جزئیات مقاله
- `/login` ورود/ثبت‌نام با کد یک‌بارمصرف
- `/account` حساب کاربری و کتابخانه خریدها
- `/admin/login` ورود مدیر و `/admin` پنل مدیریت
- `/health` health check ساده
